## 接口用法与限制

```ts
const file = await resolveWithin(allowedRoot, 'state/run.json');
await writeJsonAtomic(file, manifest, { root: allowedRoot }); // 默认只新建
// 在调用方已经确认文件归属、读取并确认旧字节后：
await writeJsonAtomic(file, nextManifest, { root: allowedRoot, expectedHash: hashBytes(oldBytes) });
```

`resolveWithin` 只返回路径，不授予未来的无条件读写权限。读取链接证据使用 `inspectPathWithin`，其 `links` 含根相对位置、原始链接文本和已验证目标。链接变动、目录变动或未解出的链接均需重新判定。根外链接、保留设备名/ADS、大小写或规范化歧义明确失败；目录内发现无法解码的原始名称也失败，不静默漏掉输入。

`canonicalJson` 只接受有限值的普通 JSON；拒绝非 JSON 值、访问器、符号键、稀疏数组、循环、非普通原型及过深数据。对象 key 排序、数组次序不变；不执行 `toJSON`。调用方不应传入 Proxy 或来自执行代码的对象，JSON 解析后的数据才是预期输入。

写入根默认为 cwd；传入其他工作区必须显式给 `root`。协作写入通过同目录独占锁串行化，竞争或遗留锁返回 WRITE_BUSY，不自动删除未知锁。进程崩溃后可能保留锁/临时文件；后续恢复工具只有核实归属后才可清理。硬链接发布不被文件系统支持时明确失败，不降级为会覆盖/产生半文件的写法。文件同步不等于断电后目录项持久性已认证。

最终验证：50 项 storage 测试通过；typecheck、lint、boundaries、build 通过；全量回归为 253 项 Vitest + 24 项 Node 原生测试，合同测试 5 项通过。独立只读复核未确认可操作缺陷，[复核结论与边界](reviews/SG-011.md) 已保留。原始文件符号链接、Linux 反斜杠文件名及含 `..` 的链接目标语义未认证，跨平台支持前必须补对应原始文件系统反例，不能继承 Windows junction 的通过结论。
