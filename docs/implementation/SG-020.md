# SG-020 — real pinned oasdiff adapter

The adapter now calls the reviewed native Windows oasdiff 1.32.1 binary and retains the actual version output, argv, process exit, stdout/stderr, source hashes, audited-input hashes and original JSON findings. It returns check facts; gate decisions remain core logic. Installation provenance and official archive/executable digests are in [tool preparation](SG-020-tool-preparation.md).

## Interface and trust boundary

`OasdiffAdapter` in `packages/adapter-oasdiff/src/tool.ts` takes a reviewed application analysis-tool identity: explicit absolute executable, exact SHA-256, tested version, and `trusted: true`. This capability is independent of business-command execution grants. It must come from trusted application deployment context, never candidate configuration, a candidate contract or PATH lookup. Missing executable/untrusted capability is BLOCKED; changed or invalid identity is ERROR. Version mismatch is BLOCKED with actual observed version evidence retained.

`breaking(base: LoadedContract, target: LoadedContract, scope?)` returns `ContractToolResult<CompatibilityFinding[]>`; `diff(...)` returns `ContractToolResult<Record<string, unknown>>`. The envelope contains `status`, `value` (null for missing/invalid results), `diagnostics`, and `evidence`. Consumers must inspect status; a null value or missing tool never means no differences. `CompatibilityFinding` preserves `raw_rule_id`, `operation_key` (`METHOD /path`, with service prefix added by its caller), mapped `rule_id`, severity, message and the entire original record.

Both inputs are cloned, strictly reloaded and capability checked before **any** child process, including `--version`. SG-019 now also owns a process-local WeakMap certificate exposed through `getContractSnapshot`: it binds the parsed projection and raw SHA-256 to the originally loaded bytes. Mutated documents, forged hashes and unregistered reconstructed LoadedContract objects cannot borrow an old source identity. Capture the returned strings before awaiting or projecting; source hash is distinct from canonical audited tool-input hash.

Each comparison creates its own temporary directory, controlled empty config, input files and home directory. It supplies a minimal environment; inherited `OASDIFF_*`, proxies, PATH and repository config cannot alter behavior. The executable is digest checked before every invocation. Timeout and output budgets are bounded; interrupted output cannot pass. Cleanup verifies that the random owned directory remains beneath its recorded parent. This is local misuse protection, not OS isolation against a same-user attacker swapping executable/files at exactly the check/use boundary.

## Commands and interpretation

All comparisons explicitly use `--format json --allow-external-refs=false --config <owned-config> --include-path-params --auto-upgrade=false --flatten-allof=false --flatten-params=false`. Breaking adds `--fail-on WARN`; diff adds `--fail-on-diff`. No upgrade, fetch, upload, browser, candidate scripts or business command is invoked.

- Valid breaking `[]` with exit 0 is PASS; mapped nonempty findings with exit 1 are FAIL.
- Valid structural `{}` with exit 0 is PASS; supported nonempty structural differences with exit 1 are FAIL.
- Tool diagnostics, unknown JSON structure, duplicate keys, unmapped IDs, inconsistent exit/output, truncated/interrupted output and tool failures are ERROR. Unknown IDs remain visible in the returned findings/raw evidence and cannot be approved as known rules.
- Loader/capability gaps are BLOCKED before execution. The caller derives INCOMPLETE from these facts.

Four rule mappings are verified against actual binary output:

| Original tool ID | StackGate classification |
| --- | --- |
| `response-property-type-changed` | `SG-CONTRACT-TYPE_CHANGED` |
| `response-required-property-removed` | `SG-CONTRACT-REQUIRED_PROPERTY_REMOVED` |
| `request-property-became-required` | `SG-CONTRACT-REQUEST_REQUIRED_ADDED` |
| `response-property-enum-value-added` | `SG-CONTRACT-RESPONSE_ENUM_EXPANDED` |

These are one-to-one mappings. Unknown rules fail closed until reviewed and tested. The structural diff reader accepts a deliberately narrow grammar for observed path/operation/response/content/schema differences and simple metadata changes; new shapes become ERROR, not guessed semantic equivalence. The original raw JSON remains in evidence even when interpretation fails. Callers own durable artifact storage; this module returns raw evidence without claiming that a Run was executed or sealed.
